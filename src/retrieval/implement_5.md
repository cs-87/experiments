## Current finding

Stage 3a runs the frozen frame-level matcher independently for every leak frame:

`SSCD → Top-K → DISK → LightGlue → RANSAC → combined score`

with:

`combined = num_inliers / (1 + median_inlier_reprojection_error)`

The resulting leak→original trajectory is already approximately linear and monotonic, with no meaningful drift or systematic offset.

On the 600-frame synthetic run:

* exact accuracy @ K=50: 34.3%
* ±1 accuracy: 59.0%
* ±5 accuracy: 87.2%
* median error: 1 frame
* mean error: 2.60 frames
* max error: 81 frames
* monotonic adjacent transitions: 78.0%

The important observation is that the errors are mostly:

1. isolated single-frame wrong predictions
2. short local streaks where the matcher temporarily selects nearby wrong frames

There is no evidence of systematic speed mismatch, persistent offset, or long-range drift.

Example of an isolated failure:

```text
leak 105 → original 103
leak 106 → original 25      ← bad outlier
leak 107 → original 105
```

Therefore, the next experiment should NOT use DTW or a heavyweight global alignment algorithm.

The goal is to test whether a small amount of local temporal reasoning can correct these frame-level mistakes.

# Stage 3b goal

Build the first temporal correction layer:

```text
frame-level matcher
        ↓
raw candidate predictions
        ↓
local temporal consistency check
        ↓
re-rank existing candidates
        ↓
final temporal prediction
```

The key constraint is:

> The temporal layer must NOT redo LightGlue matching.

It should operate on the candidate scores already generated by Stage 3a.

# Critical constraint: no global temporal alignment yet

Do NOT implement:

* DTW
* Viterbi
* dynamic programming
* global optimization
* optical flow
* Kalman filtering
* learned temporal models
* long-range trajectory fitting
* frame-rate estimation
* resampling
* temporal warping
* hard `original_frame = leak_frame`
* large sliding windows

This stage is deliberately a LOCAL experiment.

We first want to know:

> Can we eliminate isolated obviously-wrong frame predictions using immediate temporal context, without harming correct predictions?

# Preserve the visual matcher

The frame-level matcher remains exactly:

`SSCD → Top-K → DISK → LightGlue → RANSAC → combined`

Do not modify the SSCD model.

Do not modify LightGlue.

Do not modify DISK.

Do not modify the combined score.

Do not change capture simulation.

Do not introduce a new visual feature.

The only new component is the temporal decision layer.

# Important implementation requirement

Stage 3a currently saves the final best candidate, but the temporal layer needs access to the complete candidate shortlist.

Modify the pipeline minimally so that for every leak frame we retain at least:

```text
leak_frame
candidate_original_frame
candidate_score
candidate_rank
```

for all K candidates.

Also retain the frame-level winner:

```text
raw_prediction
raw_score
```

Do NOT throw away the other candidates after selecting the winner.

This is important because Stage 3b should be able to say:

> "The visual matcher preferred candidate 450, but candidate 103 was almost as strong and is much more temporally consistent."

without rerunning LightGlue.

# First temporal method: local neighbor consistency

Implement the simplest possible method first.

For a suspicious frame `i`, look at:

```text
prediction[i-1]
prediction[i]
prediction[i+1]
```

A prediction should be considered suspicious when it is strongly inconsistent with its immediate neighbors.

For example:

```text
103
104
450   ← suspicious
106
107
```

The exact threshold should NOT be arbitrarily tuned on the test result.

Define the threshold explicitly and keep it simple.

Prefer a relative/local rule rather than assuming a fixed original-video frame rate.

For example, identify a candidate as suspicious when its distance from the local trajectory implied by neighboring predictions is much larger than the normal neighboring step.

Before choosing the exact rule, inspect Stage 3a's jump distribution and explain why the chosen threshold is reasonable.

# Candidate replacement

When a frame is flagged as suspicious:

Do NOT simply force it to:

```text
previous_prediction + 1
```

Instead:

1. Look at the existing Top-K candidates for that leak frame.
2. Score each candidate using:

   * its existing visual `combined` score
   * local temporal consistency with neighboring predictions
3. Choose the best candidate according to the new temporal decision rule.

The temporal term should initially be a simple penalty, not a learned model.

Conceptually:

```text
final_score(candidate) =
    visual_score(candidate)
    - temporal_penalty(candidate)
```

However, do not arbitrarily combine quantities with incompatible scales.

Normalize scores or otherwise define the comparison in a principled, reproducible way.

Do not tune a weight by searching the test set.

# Very important: only correct suspicious frames

Do NOT globally reorder the entire predicted sequence.

The default behavior should remain:

```text
final_prediction = raw_prediction
```

unless the prediction is locally inconsistent enough to be flagged.

This lets us measure exactly whether the temporal layer is fixing errors or simply changing predictions.

# Most important metrics

Also report:

### Correction rate

How many frames were actually changed?

```text
changed_frames / total_frames
```

### Correction precision

Among changed frames, how many corrections improved the absolute error?

```text
improved_changes / changed_frames
```

### Correction harm

How many changes made a previously correct prediction worse?

Especially track:

```text
correct → incorrect
```

This is critical.

A temporal filter that removes 20 bad predictions but damages 30 good predictions is not an improvement.

### Outlier recovery


* ±1

This directly measures whether the temporal mechanism solves the problem it was designed to solve.

# Sanity checks

The temporal layer should satisfy:

1. If the raw prediction is locally consistent, it should normally remain unchanged.
2. A single catastrophic outlier surrounded by consistent predictions should be corrected when a plausible alternative exists in Top-K.
3. The system should never require another LightGlue invocation for correction.
4. The temporal layer should not access the ground truth during inference.
5. The temporal layer should not use the known fact that `ground_truth[i] = i`.
6. No frame index information should enter the visual matcher.
7. The correction should operate only on the candidate predictions/scores produced by the visual matcher.

Ground truth may ONLY be used for evaluation.

# Production-minded design

Keep the temporal layer separate from the visual matcher.

Prefer something conceptually like:

```text
Stage2Verifier
    ↓
candidate results

Stage3TemporalResolver
    ↓
final mapping
```

This separation is important because eventually the temporal resolver should be replaceable without touching SSCD/LightGlue.

The final production architecture should eventually look like:

```text
Reference video
    ↓
preprocess once
    ↓
SSCD index + DISK cache

Leak video
    ↓
frame-by-frame
    ↓
visual candidate generation
    ↓
local temporal resolver
    ↓
final leak→original mapping
```

# Do not optimize for the synthetic ground truth

The current synthetic setup has:

```text
leak frame i → original frame i
```

by construction.

Do NOT exploit this.

The temporal algorithm should be written as though the true mapping could be:

```text
leak 0 → original 143
leak 1 → original 144
leak 2 → original 145
...
```

or have a different offset/slope.

It should rely on local consistency of predictions, not equality of frame indices.
